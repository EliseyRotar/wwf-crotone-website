2. CRITICAL SECURITY ISSUES
================================================================================

C1. STORED XSS VIA BLOG SANITIZER
   File: src/lib/validate.ts:31-41, src/app/[locale]/blog/[slug]/page.tsx:28
   Risk:  CRITICAL
   The hand-rolled sanitizeHtml() regex bypasses trivially:
     - <img src=x onerror=alert(1)>  (unquoted attributes)
     - <a href="j&#97;vascript:alert(1)">  (entity-encoded)
     - <svg/onload=alert(1)>  (SVG)
     - <style>, <form>, <base> tags not stripped
   Blog content is rendered with dangerouslySetInnerHTML on public pages.
   Fix: Replace with sanitize-html or isomorphic-dompurify with explicit allow-list.

C2. CSRF ORIGIN BYPASS (startsWith prefix attack)
   File: src/lib/csrf.ts:12-14
   Risk:  CRITICAL
   ALLOWED_ORIGINS.some((o) => origin.startsWith(o)) allows
   "https://wwfcrotone.it.attacker.com" to pass because it startsWith
   "https://wwfcrotone.it". This is the only CSRF defense on all admin mutations.
   Fix: Use exact equality (===) on origin, add CSRF token for all state changes.

C3. BLOG API CSRF CHECK (code smell, not critical)
   File: src/app/api/blog/route.ts:18-25
   The `if (!session || session.role !== "superadmin")` check is correct
   but confusing. Style: use `if (!session) return 401; if (session.role !== "superadmin") return 403;`

C4. TOCTOU IN BULK-EMAIL (Manager scope bypass)
   File: src/app/api/admin/bulk-email/route.ts:32-36
   Risk:  CRITICAL
   Manager whose assignedTurns="A" can email turn B's volunteers by
   passing turnoId="B". The code uses UNION (assignedTurns + turnoId)
   instead of INTERSECTION.
   Fix: Use `canAccessTurn(session, turnoId)` to validate before including.

C5. MISSING canAccessTurn ON RECEIPT UPLOAD
   File: src/app/api/admin/receipt/route.ts:15-77
   Risk:  HIGH
   Any logged-in user can upload a receipt to any iscrizione id.
   No turn-scope check.
   Fix: Add `if (!canAccessTurn(session, iscrizione.turnoId)) return 403;`

C6. DUPLICATE TURN IDS CREATE MULTIPLE ROWS
   File: src/app/api/iscrizione/route.ts:107-177
   Risk:  HIGH
   User submits turnoIds: ["A","A"]. Two iscrizioni rows created for
   same turn with same person. Capacity double-counted.
   Fix: Dedupe `d.turnoIds` after zod parse.

C7. CSV INJECTION IN EXPORT
   File: src/app/api/admin/iscrizioni/csv/route.ts:7-58
   Risk:  MEDIUM
   Cell content not escaped for formula injection. If notes contains
   "=cmd|'/c calc'!A1", Excel auto-runs it.
   Fix: Prefix dangerous chars (=, +, -, @) with single quote.

C8. MISSING ORIGIN CHECK ON PATCH
   File: src/app/api/admin/iscrizioni/route.ts:11-14
   Risk:  MEDIUM
   PATCH iscrizioni has no validateOrigin. Mutates iscrizioni via CSRF.
   Fix: Add validateOrigin.

   16 occurrences across the codebase. No next/image, no AVIF/WebP,
   no responsive srcset. ~5 MB unnecessary bytes on gallery view.
   Fix: Replace every <img> with <Image> from next/image.

   File: src/app/[locale]/page.tsx:77-82
   LCP impact: 1.5-3s on 3G/mobile. CLS from missing width/height.
   Fix: Convert to AVIF, add width/height, use priority prop.

   Files: page.tsx, dates/page.tsx, blog/page.tsx, blog/[slug]/page.tsx, gallery/page.tsx
   TTFB 200-500ms slower per request.
   Fix: Use revalidate = 60 (ISR) for stable pages.

   File: src/components/features/BookingForm.tsx (518 lines)
   Used only on /dates but ships full 24 KB to every page.
   Fix: Dynamic import with ssr: false.

   File: src/app/[locale]/layout.tsx:14-26

P13. [MEDIUM] NO ISR/REVALIDATE
